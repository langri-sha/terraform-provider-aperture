# Contributing

Bug reports and pull requests are welcome. Please open an issue first to discuss
major changes. The only hard rules:

- All Go code passes `go vet ./...` and `go test -race ./...`.
- All Terraform examples pass `terraform fmt -check -recursive examples`.
- Commits are conventional (`feat:`, `fix:`, `chore:`, etc.).

## Layout

```
.
├── cmd/terraform-provider-aperture/   # provider entrypoint (main.go)
├── internal/
│   ├── aperture/                       # HTTP client + typed wire structs
│   └── provider/                       # plugin-framework provider + resources
├── examples/                           # provider, resource, quickstart
├── docs/                               # generated by scripts/generate-docs.sh
├── scripts/generate-docs.sh            # regenerate docs/ via tfplugindocs
├── .goreleaser.yml                     # GoReleaser build/sign config
└── .github/workflows/                  # CI (test + fmt) and release
```

## Development

```sh
go mod tidy
go vet ./...
go test ./...
```

To run examples against a local build, see
[`examples/README.md`](./examples/README.md) for the `dev_overrides` workflow.
Regenerate `docs/` with `scripts/generate-docs.sh` whenever the schema or
examples change.

## Releasing

The provider is published to the public Terraform Registry as
[`langri-sha/aperture`](https://registry.terraform.io/providers/langri-sha/aperture).
Releases are cut from the GitHub UI and built by CI:

1. Update `CHANGELOG.md` for the new version.
2. Publish a GitHub Release for the `vX.Y.Z` tag, writing the release notes there.
3. The [`Release`](./.github/workflows/release.yml) workflow runs GoReleaser
   ([`.goreleaser.yml`](./.goreleaser.yml)): it builds the cross-platform
   archives, generates and GPG-signs `SHA256SUMS`, and attaches them — plus
   `terraform-registry-manifest.json` — to the release. The registry ingests it
   automatically.

One-time setup lives outside the repo: the signing key's public half is
registered on the langri-sha registry account, and `GPG_PRIVATE_KEY` /
`PASSPHRASE` are stored as Actions secrets.
